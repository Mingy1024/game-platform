## 同步檢查表（docs/dev/sync-checklist.md 第 1、2、7 節）

沿用礦坑大逃亡的做法：伺服器只存「取最佳」的紀錄，沒有累計次數，重送一定是冪等的，不需要批次代碼。和礦坑大逃亡不同的地方只有比較規則：**分數高的較好；同分時間短的較好；再同時先創下的較好**。`mode` 是 `fixed`（固定關卡）或 `random`（隨機模式），沒有日期，第 5 節（跨午夜）不適用；本機驗證時間的上限仍是手機時鐘快 1 天。最高到達層數只存本機，不送伺服器。

### 第 1 節：共用狀態與寫入者

| 狀態 | 存在哪裡 | 誰會寫 | 怎麼避免同時寫 | 測試 |
|---|---|---|---|---|
| 本機最佳紀錄（顯示用快取） | `game-station:monk-soup-tower:v1` | 送達塔頂（`recordRun`）、同步回應（`adoptAccountRecords`）、登出清空 | 只當顯示快取；送伺服器的資料照實記在 inbox，不拿快取判斷「不用上傳」 | 單元 J1、P4 |
| 待上傳（pending） | `game-station:monk-soup-tower:pending:v1` | 只在同步的 Web Lock 裡：收 inbox、送出成功後移除已確認的、登出清空 | 第 1 種：鎖裡讀→改→寫。內容 `{ guestSyncId, bests: [{mode, score, timeMs, achievedAt}] }`，同一種只留最佳的一筆 | 單元 P4 |
| inbox | `game-station:monk-soup-tower:run:<隨機代碼>` | 送達塔頂時新增一個新 key | 第 2 種：只新增；鎖裡的同步先寫成功 pending 才刪 inbox | 單元 P8 |
| 登出記號 | `game-station:account:signed-out` | 沿用平台 | 其他分頁收到就當作已登出，epoch 作廢送出中的請求 | E2E P9 |
| 伺服器 `monk_soup_tower_bests` | D1 | `POST /records/sync`、訪客併入 | 條件更新 `WHERE score < ? OR (score = ? AND time_ms > ?)`；沒有就建立，撞到唯一鍵（P2002）重試 | 單元 P4、P7 |
| 訪客與 cookie `gs_guest` | D1、cookie | 沿用平台 | 沿用平台；`mergeGuest` 加上這張表的合併（同一個 D1 batch） | 單元 P7 |

不支援 Web Locks：不鎖。所有寫入都是取最佳，兩個分頁各送一次不會出錯；pending 的移除只移除「不比送出那筆好」的項目，多送不會丟資料。

### 第 2 節：每個請求的結果

| 結果 | 處理 | 測試 |
|---|---|---|
| 沒有回應（離線、逾時） | pending 原封不動；`online`、下一局送達、打開介紹頁或 /me 時重送 | E2E P8 |
| 伺服器已寫入但回應沒收到 | 重送同樣的 bests：取最佳冪等；建立訪客用同一個 `guestSyncId` 找回同一個訪客 | E2E T8 |
| 400 | 格式或範圍不對（正常前端不會送出）：丟掉這一批，不再重送 | E2E P5 |
| 401 | Google：`expireSession`，本機與 pending 留著；訪客 cookie 無效：`expireGuest`，pending 留著 | E2E P3 |
| 403 consent_required | pending 留著，結算顯示上榜詢問 | E2E T10 |
| 403 其他、413、429、5xx、格式不對 | 暫時失敗，pending 留著，下次重送 | E2E T9 |
| 409 account_mismatch | epoch +1、重新讀登入狀態；pending 留著送給新身分 | E2E P3 |
| 晚到的回應，期間已登出或換帳號 | epoch 或登出記號變了就丟掉 | 程式同礦坑大逃亡 |
| 晚到的回應，期間本機有更新 | 套用時取「帳號、pending、本機」三者最佳，不蓋掉新的 | 單元 P4（overlay） |
| 送到一半頁面關掉 | pending 在 localStorage，新頁面接手重送（冪等） | 單元 P8 |
| 送出後頁面關掉、沒有回應 | 同上；重送不會重複，不需要「不明確」狀態 | — |

### 第 7 節：登入狀態的結束方式

| 情況 | 本機資料 | 這一頁登入狀態 | 其他分頁 |
|---|---|---|---|
| 這一頁按登出 | 清本機最佳、最高層數、pending、inbox；最後才發布新的身分狀態 | 已登出 | 收到登出記號，epoch +1、清空、重新讀取 |
| 刪除帳號 | 同上；伺服器 CASCADE 刪 monk_soup_tower_bests | 已登出 | 同上 |
| 401（過期） | 留著（下次登入併進帳號） | `expireSession` | 各自收到 401 時處理 |
| 另一個分頁登出後可能登入別的帳號 | 已被那個分頁清掉 | 收到記號後重新讀取 | — |
| 過期後另一個分頁直接登入別的帳號 | 留著，送給目前 cookie 的帳號 | 附上的 playerId 與 cookie 不同，伺服器回 409，重新讀取 | — |
| 刪除訪客紀錄 | 同登出 | 沒有身分 | 同登出 |
