# 下班逃離辦公室驗收標準

設計稿：https://claude.ai/artifact/STatW7mmmh476qsnU7jxAt（「討論整理與規格」第 1–19 題與第 2–8 節；畫板 A1–F1）

實作完成後，逐條比對這份清單。共 121 條（2026-11-22 建立，依設計稿 v3），每條都有編號和檢查方式。結果欄實作前先留空。

## 怎麼使用

1. 實作完成後，每一條都實際執行檢查，不憑印象判斷。
2. 每條記錄結果：通過、不符、無法驗證，並附上證據（測試名稱、截圖或指令輸出）。
3. 不符的項目整理成清單，寫明現況和規格差在哪裡，然後修正。
4. 修正後重跑受影響的條目，再跑一次品質關卡（Q 組），確認沒有改壞別的地方。
5. 最後交出一份驗收報告：通過幾條、修了哪些、偏離設計稿的地方、還有哪些需要人工確認。

規格之後如果有變動，先改這份清單（必要時也改設計稿），再改程式。

## 設計稿沒寫死、本清單先採用的解讀

下列幾處設計稿的文字有兩種讀法，清單先照右欄寫。使用者看過清單時若要改，先改這裡再改下面的條目。

| 項目 | 本清單採用的解讀 |
|---|---|
| 擦身連段倍率 | 第 1 次擦身 ×1.0（50 分）；連續第 2 次 ×1.1，之後每次 +0.1，最高 ×1.5；被撞到、被耽誤歸零。擦身分＝50 × 當下倍率，四捨五入 |
| 時間分的「用時」 | 該段從進入到穿過段尾線的時鐘時間，**含**被耽誤跳走的秒數；比目標早到每 0.1 秒加 10 分（不足 0.1 秒捨去），晚到不扣分、最低 0 |
| 準時倍率邊界 | 剛好 18:01:00.0 算 ×2.0、剛好 18:01:30.0 算 ×1.5（邊界歸在較好的那一級，和精準停車一致）；時鐘走過 18:01:30.0 還沒穿過旋轉門就是被攔下 |
| 突發事件三個選項 | 每題固定 1 個最佳、1 個普通、1 個錯誤，順序每局隨機；超時算選錯 |
| 被主管叫住的耽誤 | 該段第一次視線接觸觸發突發事件；同一段第二次改成停 1 秒（設計稿第 2 節） |
| 道具效果 | 咖啡：前進速度 ×1.4 持續 3 秒；耳機：3 秒內同事不會搭話（主管視線仍有效）；勿擾模式：擋掉下一次突發事件，該段視為已觸發過 |
| 記錄與排行 | 本遊戲只存本機最佳；全站排行、Google 登入同步先留版位（設計稿第 8 節「線上排行與帳號，先留版位」），不做伺服器紀錄表 |

## 需要你人工確認的項目

這些我沒辦法自己驗證，驗收報告會另外列出，請你確認：

- 實機手感：滑動換線與跳躍的靈敏度、難度曲線（第 1 段到第 4 段）、3 秒突發事件夠不夠
- 數值定案：目標時間 20／25／20／15 秒加起來 80 秒，而時鐘有 90 秒，實際能拿到 ×2.0 的寬裕度需要試玩後調整
- 系統分享選單：帶到 LINE、Instagram 等 App 之後實際長什麼樣子
- 翻譯品質：日、韓、越、葡文的 60 句台詞是否自然，需要母語者看過
- 美術觀感：three.js 角色、電梯廳背景、特效是否協調
- 音檔聽感：音量平衡、奔跑聲循環、背景音樂接縫（音檔由你生成後交檔）
