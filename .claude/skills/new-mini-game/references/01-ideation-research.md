# 階段 1–2：選題與研究

## 選題

使用者通常只給大方向，例如「手機電腦都能玩、夠有趣、會想重複玩」。列 3–6 個題材，每個寫：

- 一句話玩法（玩家實際在做什麼動作）
- 為什麼會想再玩一次（分數追求、每日挑戰、連擊、短局數）
- 單指或單鍵能不能玩（平台遊戲要手機電腦都能玩）
- 一局多久（平台定位是一兩分鐘一局）
- 實作難度與風險（物理、美術量、判定精度）

已經上架的遊戲在 `lib/catalog/catalog.ts`。避免和現有遊戲玩法太像，也要確認分類（`lib/catalog/categories.ts`）放得進去。

**關卡**：使用者選定題材才進研究。

## 研究

研究的目的是讓需求確認時的每個建議都有根據。範圍：

1. **類似遊戲**：找 4–6 款，寫操作方式、計分方式、可以借鏡的地方。只借鏡機制，不沿用名稱、角色、介面或用語，並在摘要最後寫明這一點。
2. **玩法拆解**：核心動作、失敗條件、難度怎麼上升、什麼讓人想重玩。
3. **計分方式**：精度、時間、連擊等常見組合，以及怎麼防止「一種打法通吃」（精準停車用超時扣分防止一開始猛煞再慢慢爬）。
4. **技術做法**：引擎（平台用 Phaser 4）、固定時間步進、可重現的亂數種子、哪些邏輯能寫成不依賴引擎的純 TypeScript 模組並單元測試。

研究摘要會放進設計稿（「研究摘要：類似的遊戲」一段），所以寫成表格：遊戲｜操作｜可以借鏡的地方。

**關卡**：研究摘要給使用者看過，再開始一題一題確認。研究完成後直接進入第一題即可，不需要另外等一輪「可以開始問了嗎」。
